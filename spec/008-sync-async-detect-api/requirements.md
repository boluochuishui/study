# 需求说明

## 背景

不同内容的检测耗时存在明显差异。文本和图片可以快速返回结果；音频和视频涉及下载、ASR、抽帧和模型推理，需要通过消息队列异步处理。

## 目标

- `POST /api/detect/sync` 只支持文本和图片，直接返回检测结果。
- `POST /api/detect/async` 支持文本、图片、音频和视频，任务写入 RocketMQ 后返回 `202 Accepted`。
- `taskId` 由服务端生成，同一次提交只对应一个任务 ID。
- 外部租户通过平台 RocketMQ 的独立结果 Topic 获取异步结果。
- 不保存任务数据库，不提供任务状态查询接口。
- 检测执行异常时执行故障开放，返回或发送 `FAILED + PASS + degraded=true`。
- 检测过程不对外开放，使用结构化日志记录，后续通过 Elasticsearch 存取。

## 能力矩阵

| 内容类型 | 同步接口 | 异步接口 |
| --- | --- | --- |
| `TEXT` | 支持 | 支持 |
| `IMAGE` | 支持 | 支持 |
| `AUDIO` | 不支持 | 支持 |
| `VIDEO` | 不支持 | 支持 |
| `MULTIMODAL` | 不支持 | 不支持 |

## 约束

- 客户重复提交视为多个独立任务，每次生成不同 `taskId`。
- RocketMQ 使用至少一次投递语义，同一 `taskId` 的消息可能被重复投递。
- 第一版允许少量重复检测，不增加数据库或 Redis 去重。
- 客户按照 `taskId` 幂等处理结果消息。
- 故障开放只针对检测执行失败；鉴权失败、参数错误和 MQ 提交失败不能放通。
- 服务完全不可访问时，由调用方 SDK 或上游系统决定是否放通。

## 非目标

- 不提供 `GET /tasks/{taskId}` 查询接口。
- 不使用 Elasticsearch 承担任务状态或分布式锁。
- 不向客户自建消息队列投递结果。
- 不承诺恰好一次投递或跨任务顺序。
- 不实现批量检测和多模态检测。
