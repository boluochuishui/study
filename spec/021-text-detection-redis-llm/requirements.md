# 021 文本检测、Redis 违规缓存与异步大模型预留

## 背景

文本检测需要形成可运行的责任链。明确违规样本占比较低，重复样本可通过 Redis 快速返回历史违规结果，同时不能在缓存中保存文本原文。大模型耗时和成本较高，只允许异步检测流程调用。

## 需求

1. 文本进入检测链后先进行稳定归一化，并计算 SHA-256 指纹。
2. Redis 键和值均不得包含文本原文，只保存样本指纹和最终违规结论。
3. 只缓存最终动作是 `REJECT` 的结果，不缓存 `PASS`、`REVIEW` 或降级结果。
4. 缓存命中后直接返回历史违规结果，不再执行后续规则和模型节点。
5. 文本本地检测至少包含关键词和联系方式正则检测，并由统一决策节点汇总。
6. 预留大模型检测 SPI；同步请求必须跳过大模型，异步请求才允许调用。
7. Redis 或大模型不可用时记录详细内部日志，检测链继续执行，不向外暴露内部过程。
8. 缓存 TTL、键前缀、决策版本和大模型开关通过配置项管理。

## 非目标

- 本需求不实现真实大模型供应商客户端。
- 本需求不实现管理台配置页面。
- 本需求不缓存正常样本，也不把任务状态写入数据库。
