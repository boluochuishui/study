# 025 服务优雅上下线

## 背景

接入层、管理台、四个检测微服务需要在初始化完成后接收业务，并在滚动发布时限时完成已接收的任务。现有 TCP 探针不能判断规则快照是否就绪，线程池退出也缺少统一时间预算。

## 验收标准

- 服务使用 STARTING、READY、DRAINING、STOPPED 单向状态，摘流操作幂等。
- 责任链已装配、已注册热加载模块首次全量快照成功、RPC 已导出才允许上线。
- HTTP 业务入口和检测 RPC 拒绝未就绪、下线中的新任务。
- 异步任务计数覆盖检测和结果 MQ 的发送确认，已接收任务继续执行。
- Kafka 监听器就绪后启动，下线后暂停；未被接收的消息不得因下线异常提交偏移量。
- 线程池共用剩余时间预算，超时日志必须记录未完成工作。
- K8s 使用应用级探针、preStop 和滚动更新，停机总宽限大于应用收尾预算。
- 手工摘流仅允许本机请求和专用 Secret 令牌；不提供重新上线接口。
- 注释和文档中文，异常信息英文，不在日志中记录令牌。

## 范围

实现通用生命周期模块及现有服务适配，不引入蓝绿、金丝雀发布。前序责任链异步后置步骤尚未实现，本需求接入现有受管线程池的收尾能力，不声称已实现 Redis 异步节点。SIGKILL、宕机及超过任务期限的长任务允许中断，遵循既有弱一致性设计。
