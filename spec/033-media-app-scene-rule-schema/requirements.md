# 需求 033：媒资、应用、场景与检测规则表设计

## 需求范围

补充六张业务表：媒资库、媒资、媒资与媒资库关联、检测规则、App、场景。设计已确认，本轮实施 V9 建表迁移；数据库 SDK 和管理接口按后续需求实施。

## 约束

- 六张表均按 `tenant_id` 隔离，并包含 `created_by`、`created_at`、`updated_by`、`updated_at`。
- 沿用需求 032 的服务端操作人填充，系统操作人使用 `0`。
- 媒资与媒资库多对多关联，同一文件在租户内去重，在不同库中可以有不同的标注。
- 媒资表保存名称、类型、内容摘要、哈希版本、准备状态和备注，不保存正文或 Base64。
- 按用户确认移除 `storage_ref`、`mime_type`、`size_bytes`、`duration_ms`、`width`、`height`，不新增替代这些信息的字段。
- 第一版场景归属一个 App，检测规则归属一个场景；场景可以配置多种检测类型。
- App 的外部 `app_id` 与现有 `X-App-Id` 对应，场景编码与现有 `sceneCode` 对应。
- 检测规则复用现有 SpEL 发布快照，数据库仍只保存表达式源码，不保存 JVM 编译对象。
- 大模型规则只允许异步检测；新增规则不会动态重排责任链节点。
- 本需求不改变检测任务持久化、Redis 违规结果缓存与 Elasticsearch 过程日志的现有边界。
