# 014 设计

## 扩展接口

`HotLoadSource<K,V>` 提供 `loadFull()` 和 `loadChanges(afterCursor, limit)`。`HotLoadModule<K,V,R>` 提供名称、数据来源和 `compile(items)`。业务模块注册为 Spring Bean 后由管理器自动发现。

全量结果包含完整数据和全局变更游标，二者必须在数据库同一一致性视图中读取。增量数据必须来自可靠的变更流水，包含 `UPSERT` 与 `DELETE` 事件；当前 `sdk_config_item.version` 是单行乐观锁版本，不能直接充当全局游标。

## 生命周期

1. 应用就绪时逐模块尝试全量加载。
2. 定时器逐模块查询至多 `batchSize` 条增量变更。
3. 复制当前原始数据并顺序应用变更。
4. 业务模块编译和校验整份候选快照。
5. 成功后以单次引用赋值切换快照与游标，失败时二者都不变。
6. 达到全量校准周期时重新加载完整数据。

请求读取的已编译结果应由业务模块保证不可变，或内部只使用不可变结构。框架以不可变 `Map` 保存原始数据。模块未初始化时 `getRequired` 明确失败，是否使用业务默认值由接入方自行决定。

## 配置

`base-sdk.hotload.poll-interval-ms` 默认 30000；`full-refresh-interval-millis` 默认 3600000；`batch-size` 默认 500。全量间隔为 0 时每次刷新都执行全量加载，可用于校准和测试。

第一版不提供分布式通知。每个实例独立轮询、独立切换，属于最终一致。后续可以增加通知触发，但仍保留周期性全量校准。
