# 014 通用定时热加载框架需求

## 背景

业务配置需要在不重启服务的情况下从数据库进入本地内存。不同业务对原始数据的解释不同，但全量初始化、按游标增量同步、快照切换和故障保留旧版本可以复用。

## 需求

- 在 `baseSdk.hotload` 提供与业务模型、数据库实现解耦的通用框架。
- 应用就绪后尝试全量加载，后续按固定间隔执行增量同步。
- 支持新增、修改、删除；增量必须按游标严格递增。
- 定期重新全量加载，校准漏同步或数据漂移。
- 新快照编译失败时保留上一有效快照和游标。
- 各模块独立刷新，单模块故障不得阻断其他模块。
- 提供当前快照读取与运行状态查询。
- 第一版不接入任何业务模块，也不改动现有鉴权刷新逻辑。
