# 027 批量检测与二进制上传

## 需求与边界

- 一个请求只包含一种 contentType，服务端生成一个 taskId。
- 文本和图片支持同步、异步批量；音频和视频先支持单文件异步。
- 同步返回聚合结果，异步投递一个任务并发布一条包含所有项目结果的消息。MQ 重投递仍需消费方按 taskId 幂等。
- 支持 JSON 文本/统一 URL，以及 multipart/form-data 直接上传文件二进制，不要求客户预先上传或 Base64 编码。
- itemId 请求内唯一，language、region、sceneCode 整批共用；appId 沿用鉴权请求头，不接受请求体身份覆盖。
- 数量、文本长度、单文件、总请求大小和图片像素数限制可配置。
- 格式、重复编号、总量超限拒绝整批；损坏文件等逐项错误保留在聚合结果，其余继续。
- 每项独立执行责任链，不暴露内部步骤。检测异常降级放通必须明确标记，不能当作正常通过。
- 保留既有单条接口；不改数据库结构、不实现真实 OCR/ASR/图片模型。

## 验收

验证 JSON 和 multipart、上传验签、同类型/数量/大小限制、逐项失败、顺序关联、RPC 路由、异步单次聚合发送、文件保存和清理、安全路径约束及旧接口兼容。
