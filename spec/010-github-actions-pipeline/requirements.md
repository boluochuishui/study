# 需求说明

## 背景

项目需要建立不依赖个人 IDEA 配置的持续集成与手动发布构建能力，使代码提交和版本构建使用同一套可追溯质量标准。

## 持续集成

代码推送或面向 `main` 的 Pull Request 触发以下步骤：

1. 使用 Java 21 编译项目。
2. 执行单元测试。
3. 执行 Checkstyle。
4. 执行 SpotBugs。
5. 生成 JaCoCo 覆盖率报告并校验最低覆盖率。
6. 无论成功失败均保存可用的质量报告。

## 手动发布构建

通过 GitHub Actions 手动输入版本号，执行以下步骤：

1. 校验版本号格式。
2. 设置本次构建版本，不提交对 `pom.xml` 的修改。
3. 编译并执行完整质量门禁。
4. 构建可执行 Spring Boot Jar。
5. 上传 Jar、测试报告和质量报告。
6. 构建带版本标签的 Docker 镜像，但当前阶段不推送镜像仓库。

## 验收标准

- 本地执行 `mvn clean verify` 与 CI 使用相同质量门禁。
- 任一测试、Checkstyle、SpotBugs 或覆盖率检查失败时流水线失败。
- JaCoCo 行覆盖率最低门槛为 60%，后续随测试完善逐步提高。
- Docker 镜像以非 root 用户运行。
- CI 使用最小 GitHub Token 权限，并避免同一分支过期任务浪费资源。
